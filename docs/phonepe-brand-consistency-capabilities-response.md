## 1. Executive Summary

PhonePe has evolved from a payments app into a multi-product portfolio. Brand equity is strong, but visual expression has drifted across products and touchpoints.

This is not a rebranding exercise. PhonePe has asked us to audit, strengthen, and extend the existing identity — build a flexible system for future growth — while Share.Market, PhonePe Business, Indus Appstore, and other brands keep their individual identities.

Our response maps directly to PhonePe's five workstreams and six deliverables (Sections 3–6).

Brucira will deliver:

- Audit → principles → extended system → signatures → application proof
- Figma library, guidelines, and application proof — the core engagement
- Optional development — Brucira developers (1–2 FTE) for coded tokens, components, and Storybook if PhonePe wants implementation from us (Section 9.3)
- Ongoing governance — templates, review gates, and measurable consistency post-delivery

Boundaries we respect: no logo, name, or core purple change; no repositioning; no UX redesign; no new identity from scratch; no overall brand strategy rewrite.

## 2. Understanding PhonePe's Mandate

### 2.1 The Challenge

- Inconsistent illustration, typography, colour, and graphic elements across products and touchpoints
- No unified system linking portfolio brands back to PhonePe
- Need for coherence without making every product look the same

### 2.2 The Objective

- Audit the current visual identity and identify improvements
- Define design principles aligned with existing brand strategy
- Extend the existing system (10 areas) — build on equity, not replace
- Create recognition beyond logo and purple
- Demonstrate the system across digital and physical touchpoints

### 2.3 Core Tension — *One ecosystem, many expressions*

| Requirement | Implication |
|-------------|-------------|
| Portfolio coherence | Every touchpoint feels recognisably PhonePe |
| Product individuality | Each brand serves a distinct audience |
| Preserve equity | Logo, name, core purple unchanged |
| No UX redesign | Visual system work only |

Product audience context:

| Brand | Expression need |
|-------|-----------------|
| PhonePe Consumer | Mass India reach — clarity, trust |
| PhonePe Business / Merchant | Familiar, locally relevant |
| Payment Gateway | Professional, partner-facing |
| Share.Market | Modern, investing-native |
| Indus Appstore | Category-relevant, parent-connected |
| PhonePe Pulse / Pulse Pro | B2B / analytics tone |

### 2.4 Out of Scope

- Logo redesign · Name change · Core purple change · Brand repositioning
- Product UX redesign · New identity from scratch · Overall brand strategy

## 4. Five-Phase Methodology

### Phase 1 — Discovery & Audit (Months 1–2)

Activities: Asset collection across Section 3.2–3.3 · Stakeholder interviews · Score samples 1–5 (colour, type, illustration, photography, iconography, motion, graphics, layout, sonic, verbal tone) · Map fragmentation, overlap, and gaps

Outputs: Audit report · Brand × touchpoint heat map · P0/P1/P2 backlog · Executive summary (top 10 remediation items)

---

### Phase 2 — Design Principles & Brand Architecture (Month 2–3)

Objective: Principles for PhonePe Consumer, Merchant/Business, Payment Gateway, Share.Market, and Indus — across and within each brand — aligned to existing brand strategy.

Activities: Synthesise audit · Principles workshop · Group principles + sub-brand flex zones · Decision rules (not abstract adjectives)

Principle format: `Principle → Meaning → Do/Don't → Applies to (Group / Consumer / Business / Share.Market / Indus)`

Outputs: 5–7 design principles · Sub-brand architecture (Section 5) · Principle-to-touchpoint matrix

---

### Phase 3 — Evaluate & Extend the Existing System (Months 3–6)

Evolution, not replacement. No logo, name, or core purple changes.

Ten system areas:

| Area | Extend |
|------|--------|
| Colour palette & usage | Hierarchy, accessibility, print/digital parity |
| Typography | Type scale, pairing, fallbacks |
| Illustration | Master style + sub-brand variants |
| Photography | Art direction, treatment standards |
| Iconography | Unified library |
| Motion design | Beam audit, timing, signature transitions |
| Graphic & visual assets | Patterns, shape language |
| Layout & composition | Grid, spacing, responsive rules |
| Infographics | Chart and data-viz templates |
| Sonic | Standardise or extend sonic signatures |

Outputs:

- Extended system specification + revised changes log (if audit requires)
- Figma library, variables, Do/Don't galleries (×10 areas)
- Guidelines for applying the system across products and touchpoints

**Optional (if PhonePe engages Brucira developers — Section 9.3):** Developed design system in code — tokens, core components, Storybook · Figma variables synced to code tokens · live component docs · accessibility defaults in components

Core deliverable is design-ready: Figma library and specs extend existing PhonePe assets — audit, integrate, don't rip-and-replace. Engineering implementation is PhonePe's team or Brucira developers on optional scope.

---

### Phase 4 — Brand Recognition & Recall (Months 4–6, parallel with Phase 3)

Central question: *What distinctive, repeatable signatures create instant recognition — while Share.Market, Indus, and other brands keep individual identities?*

Activities: Inventory beam, motion, sonic, interaction, communication style · Classify each as strengthen / evolve / standardise / create · Define signature system (visual, sonic, verbal, interaction-led) · Application rules per touchpoint

Outputs: Signature asset documentation · Usage rules for product, campaign, social, advertising, films, podcasts, events, motion, and sound

---

### Phase 5 — Demonstrate the System (Months 6–8)

Application examples:

Product UI · Websites · Marketing design assets · Social media · Merchant branding · Events · Corporate communications · Investor relationship · Print media

Each example: Before (drift) → System applied → Sub-brand variation (where relevant)

Outputs: Mockups + before/after sets · Template starter kits · Comprehensive brand book and toolkit

Phases 3–5 overlap from Month 3 onward where dependencies allow. **Total engagement: 6–8 months** — core deliverables by Month 6–7; Month 7–8 for governance handover, review gates, and PhonePe sign-off.

### Pine Labs

**FINTECH · MERCHANT COMMERCE**

**Context**

Pine Labs' acquired companies operated with completely different websites, visual languages, and user experiences, which created a fragmented digital ecosystem. At the same time, the existing Pine Labs brand felt dated and was not equipped to represent a rapidly expanding portfolio. There was a shared need to bring all products and services under Pine Labs as unified offerings while also rethinking the brand guidelines to reflect its scale, innovation, and future direction.

**What we did**

We collaborated to consolidate multiple brand experiences into one cohesive digital umbrella, repositioning individual products and services as integrated Pine Labs offerings. In parallel, the teams worked on a comprehensive brand guideline rehaul, supported by UX research, iterative design, motion, 3D, and a refreshed visual system to create a modern, scalable, and consistent identity across the entire ecosystem.

**Outcome**

A unified, future-ready digital experience for Pine Labs — a cohesive digital ecosystem that brings together diverse products and services under one bold, technology-first identity. Built on clarity, innovation, and scalable design, the new Pine Labs website reflects a brand ready to lead the future of integrated commerce.

*Relevance to PhonePe:* Multi-surface fintech portfolio — website, design system, and asset library at national scale.

---

### BharatPe

**FINTECH · FIRST-TIME DIGITAL USERS**

**Context**

As BharatPe's offerings expanded, its digital presence needed to go beyond enabling transactions and build confidence from the very first interaction. The challenge was to simplify complex financial interactions while clearly communicating reliability, transparency, and ease of use to a broad and evolving user base.

The digital experience needed to establish trust quickly, guide users effortlessly, and position BharatPe as an everyday financial companion rather than just a functional tool.

**What we did**

We redesigned BharatPe's digital experience with a focus on clarity, intuitive flows, and visual consistency. The experience was structured to reduce cognitive load, guide users with confidence, and reinforce trust through clear hierarchy, thoughtful interactions, and a cohesive design system.

**Outcome**

The final app reflects a minimalist yet sophisticated design approach, where each screen presents only what is essential at that moment while still allowing access to deeper information when needed. Key user journeys — from onboarding and success states to transaction history, bill payments, EMI tools, and value-added features like gift cards — are structured to feel focused and intuitive. By thoughtfully layering information and using clear visual hierarchy, the experience reduces cognitive load while maintaining consistency and flexibility across the app.

*Relevance to PhonePe:* Mass-market payments app and design system — product consistency at scale for a broad user base.
